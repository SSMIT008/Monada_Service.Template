Quick Start

From package to running service.

Add GitHub Packages

Create a PAT with read:packages, keep it out of source control, and register the package feed.

$env:GITHUB_PACKAGES_TOKEN = "YOUR_PERSONAL_ACCESS_TOKEN"
    dotnet nuget add source "https://nuget.pkg.github.com/SSMIT008/index.json" `
    --name github-ssmit008 `
    --username SSMIT008 `
    --password $env:GITHUB_PACKAGES_TOKEN

Install the template

dotnet new install Monada.Service.Template@1.0.0 `
    --nuget-source "https://nuget.pkg.github.com/SSMIT008/index.json"

Create a service

dotnet new monada-service -n Monada.Realtime

Build and run

cd Monada.Realtime

dotnet restore
dotnet build
dotnet watch --no-hot-reload

Swagger UI: https://localhost:8000/swagger

CI/CD

Versioned publishing through Git tags.

The release workflow derives the NuGet version from a tag, builds the package in Release mode and publishes it to GitHub Packages.

Release

git status
git add .
git commit -m "Improve Monada service template"
git push origin main

git tag v1.1.0
git push origin v1.1.0

Workflow result

v1.1.0 becomes package version 1.1.0.

The pipeline checks out the tagged source, configures .NET 10, packs the template and publishes the immutable package version.

Verification: GitHub - Actions and GitHub - Packages.

Engineering Philosophy

Designed with intent.

A template should make the right path easier, not make architecture automatic. Domain stays independent. Dependencies stay explicit. A new service exists only when its responsibility deserves a boundary.

Build once, reuse deliberately.

Instead of recreating solution structure, references, Swagger and DI for every project, improve the foundation once and let future services inherit the standard.

Perfect means intentional.

Not endless polishing. Understand why each piece exists, choose the cleanest reasonable solution, and build something worth reusing and shipping.

Monada

A tool born from a real product.

The template was created while evolving Monada - "A hidden digital sanctuary composed of Rooms." It gives future services a shared foundation while letting the product roadmap decide when a separate boundary is actually valuable.

Identity

Users, authentication and invitations when separation becomes valuable.

Realtime

Live chat, radio, voice and streaming infrastructure.

Media

Files, images, audio/video storage and processing.

Notifications

Delivery, queues, retries and communication channels when needed.
